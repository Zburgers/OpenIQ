### 4. Proposed form-manifest schema (content-free; IDs/params only)

Two files, never merged. The manifest is trackable because it carries **no item text, stimuli, or answers** — hashes and IDs only.

**A. `forms/<form_id>/<form_version>/manifest.yml` (tracked, content-safe):**

```yaml
form_id: openiq-<construct>-<n>        # stable, human-readable
form_version: 0.1.0                     # semver; any item change = minor/major bump
items:                                  # ordered administration sequence
  - item_id: <stable bank ID>           # e.g. OMIB item ref, MaRs item ref
    item_version: <content hash>        # sha256 of canonicalized item content, NOT content itself
    source_bank: omib | mars-irt | sandbox
parameters:
  model: 2PL
  source_commit: <git sha>              # commit where param file was read
  source_path: <tracked path of param export>
scoring_code_version: <git sha of scoring module / package version>
frozen_at:
  manifest_sha256: <sha256 of canonical JSON of items+parameters+versions>
  frozen_commit: <git sha>
  frozen_by: <role>                     # never the test-taker of this form
blinding_ref: <opaque ID>               # POINTER ONLY → see B
```

**B. `blinding record` (kept separate, untracked/private):** maps `blinding_ref` → sealed-form status, exposure log (who/when/what channel), administration date, and test-taker identity. Never merged into A, never rendered into README/PR/logs/screenshots. A reviewer with only A can verify integrity (`manifest_sha256`) without learning which items are on the personal form; B answers "was it previewed?" without carrying content.

**Invariants:** in-place item edit ⇒ new `item_version` + form_version bump, never mutation of a frozen `manifest_sha256`; scoring code change ⇒ new `scoring_code_version` + re-freeze; MaRs and OMIB forms ship separate manifests (no shared θ, no averaging) per `PROTOCOL.md`.

No ICAR material touched. No personal-form preview. No redistribution assumed. — J.O.
